# Repository audit — 6 September 2026

The audit covered the showcase, waitlist Workers, content and agent documents,
components and motion, assets, tests, dependencies, CI, and repository guidance.
Existing work was first preserved in six logical commits. The fixes below were
then checked locally on Node 24.18.0 and pnpm 11.24.0.

## Corrections

### Authentication and data handling

- Replaced handwritten JWT parsing and verification with `jose`, following
  [Cloudflare's validation guidance](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/validating-json/).
  Verification checks RS256, issuer, audience, expiry, time claims, and identity.
  Malformed claims and unsupported critical headers are rejected. The library
  handles remote signing-key caching and refresh.
- Made deletion and its audit record one D1 transaction. A regression test
  forces the audit insert to fail and verifies that the subscription survives.
  [D1 batch semantics](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)
- Split first-page and cursor queries so SQLite can seek through the
  `(brand_id, joined_at, id)` index. `EXPLAIN QUERY PLAN` confirmed the cursor
  query uses the tuple range; equal-timestamp pagination is covered by a test.
- Limited form bodies to 8 KiB before parsing, including streamed requests.
  Tests cover oversized and malformed bodies.
- Removed exception text from application error logs so an upstream error
  cannot copy addresses or authorization details into them.

### Components and browser behaviour

- Extracted scroll coordination from the showcase component. Row animations
  clean up on teardown, and user input cancels a running scroll glide.
- Made the WebMCP open action idempotent and await the Svelte update before
  reporting success. Registration remains feature-detected and follows the
  [current draft](https://webmachinelearning.github.io/webmcp/).
- Kept invalid form input after enhanced submission, associated the input with
  its error, and added a status region for successful joins.
- Corrected low-contrast hover and error text without changing the seven brand
  hues. Small text on ink uses a lighter blend; text on paper keeps its ink
  colour. The waitlist's hovered button and error state pass automated contrast
  checks for every weekday on desktop and mobile. The threshold comes from
  [WCAG text contrast requirements](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum).
- Used Tailwind's inline theme references so locally scoped brand overrides
  work in Storybook. All seven marker hover colours were checked in the built
  story. [Tailwind variable references](https://tailwindcss.com/docs/theme#referencing-other-variables)

### Assets and build boundaries

- Corrected the Workers Assets header pattern for brand icons and removed a
  conflicting resource-policy header. A runtime test checks the actual binding.
  [Workers Assets headers](https://developers.cloudflare.com/workers/static-assets/headers/)
- Removed the waitlist's unused italic font preload, avoiding a roughly 39 KiB
  request on its landing page, and included the distributed font's licence.
- Scoped service-worker cleanup to this application's cache names. A browser
  test verifies that an unrelated cache survives activation.
- Restored built-JavaScript checks for leaked Storybook code while allowing
  ordinary documentation mentions. Added fixture tests for both artifact types.
- Rejected ambiguous URL separators and duplicate content links before rendering.
- Added waitlist type checks to the umbrella test command. Updated CI actions
  and validated the workflow with `actionlint`.

### Copy and documentation

- Rewrote the profile README around the work and its constraints, removing
  unsupported claims about inherited proof, universal passive libraries, and
  broad industry adoption.
- Corrected Goatmire 2026 to a scheduled talk: the
  [conference dates](https://goatmire.com/) were still in the future on the audit date.
- Removed the five venture links after repeated HTTPS checks timed out.
  Restore them after the intended destinations are live. The other 22 public
  repository, documentation, and talk links checked returned successful responses.
- Compared library descriptions with twelve public repository READMEs. This
  checks attribution and description; it is not an independent audit of those
  libraries or their formal-verification claims.
- Removed premature shipping and hosting-cost promises from venture copy.
- Reconciled deployment documentation with the actual Pages and Workers
  configurations, corrected paths and hook guidance, and separated provisioned
  resources from intended production setup.
- Corrected the privacy draft's description of IP-based rate limiting and
  provider logs, and advanced its notice version to 6 September. The draft still
  requires review against the operation before collecting production addresses.

## Dependencies

Updated Playwright to 1.63.0, Wrangler to 4.129.0, vitest-browser-svelte to 3.1.0,
and the waitlist's Node 24 types to 24.13.3. Added `jose` 6.2.12. Other direct
library versions were checked against registry releases and peer constraints.

A targeted override moves SvelteKit's transitive `cookie` dependency to 0.7.2,
which fixes [GHSA-pxg6-pf52-xh8x](https://github.com/advisories/GHSA-pxg6-pf52-xh8x).
The final `pnpm audit` result contains zero known advisories.

Vitest remains on 4.1.11 because the installed Cloudflare test integration and
Storybook addon declare compatible Vitest 4 peer ranges, not Vitest 5. TypeScript
remains on 6.0.3 because the repository's export checker uses the legacy compiler
API, which the TypeScript 7 native package does not provide as a drop-in API.
The repository's pinned pnpm 11 toolchain was retained. These major upgrades
need separate migrations, not forced peer overrides.
